# Demo environment (synthetic data)

Runs the console against **synthetic** events generated by `evalkit`: no real data, no external service. Intended for presentations and for trying the product.
The message shapes resemble four common monitoring tools (Dynatrace, LogicMonitor, SolarWinds, vRealize Operations) but are **not vendor formats**.

## Start

```
cd stacks/aiops-console/demo
docker compose up -d
```

This starts VictoriaLogs and the console, then a one-shot `demo-init` container that loads the asset model (CMDB), the noise rules and three days of history
(about 60 000 events plus the critical alerts among them). UI: <http://127.0.0.1:8095>. The login token is `CONSOLE_ADMIN_TOKEN`
(demo default in `docker-compose.yml`; set your own: `CONSOLE_ADMIN_TOKEN=... docker compose up -d`).

Optional:

```
docker compose --profile live up -d                    # continuous live event stream (about 0.2 events/s)
docker compose run --rm loader storm --root esx-02     # pull the plug: one hypervisor fails, dependent assets alert within ~60 s
docker compose run --rm loader storm --root sw-core-1  # a core switch fails (largest blast radius)
```

```
docker compose run --rm loader novel                   # a few never-seen message shapes: appear as "new pattern" findings after the next scan (every 5 min)
```

After about 90 seconds (the settle window) the storm becomes **one incident** with a root-cause hypothesis instead of a dozen separate alerts.
Roots: `esx-01..08`, `sw-acc-01..04`, `sw-core-1`, `sw-core-2`.

## What works without an LLM

Correlation (topology based, one incident per storm), noise rules, new-pattern and rate-spike detection, the log volume graphs, proposals,
the Supervisor in `mock` mode (deterministic, no model) and the audit log. The AI triage text of an incident and the daily digest need a model:
set `OLLAMA_URLS` (default `http://host.docker.internal:11434`, i.e. an Ollama on the host) and `MODEL`.

## Measurement report

`python -m evalkit report --data DIR --known evalkit/examples/known.good.json --html report.html` writes a one-page report (safety gate, funnel, one storm walkthrough);
see `evalkit/examples/sample-report.html`. Run it from `stacks/aiops-console`.

## Reset

`docker compose down -v` removes all data (re-running `demo-init` on existing data would duplicate the history).

## Limits

- Synthetic data: the mechanics are real, the reduction numbers are not a promise for real production alerts.
- The alert records are written by the loader (as an alert rule such as vmalert would); real alert pipelines carry more fields.
- The demo uses the published image `ghcr.io/addamka84/aiops-console` (override with `AIOPS_IMAGE`).
